# AB OPEN WORLD — إعادة بناء Native لنظام Android

هذا المشروع يعيد بناء اللعبة باستخدام **React Native لواجهة التطبيق** و **Three.js فوق Expo GL/OpenGL ES** للرسم ثلاثي الأبعاد. لا يستخدم WebView ولا يشغّل ملف HTML داخل التطبيق.

## ما يحتويه المشروع

- ملف `assets/Man.glb` الأصلي مضمّن داخل التطبيق. فحص الملف يبين وجود 68 مفصلاً و7 حركات: `agree`, `headShake`, `idle`, `run`, `sad_pose`, `sneak_pose`, `walk`.
- سماء بتدرج النهار/الغروب/الساعة الزرقاء/الليل، وهج الشمس والقمر، سحب إجرائية، ضباب متغير، أرض قابلة لتغيير اللون وإضاءة ديناميكية. معادلات لوحة السماء الأساسية من ملف HTML المرجعي.
- مرايا بيئية منخفضة التكلفة: أي Mesh اسمه يحتوي `Mirror` (بأي حالة أحرف) يستبدل بخامة Shader تعكس اتجاه السماء/الشمس/الأرض/الضباب فقط. لا تنفذ Render Pass ولا تعكس الشخصية أو بقية المجسمات.
- AnimationMixer لتشغيل الحركات المضمنة في Man.glb.
- محرر عظام يتعرف على مفاصل الجسم الشائعة ويطبق تدوير X/Y/Z بعد تحديث الأنيميشن، مع إعادة الضبط ووضعية قبضة اليد.
- استيراد GLB، واستيراد GLTF مع تحديد ملف `.bin` والصور المصاحبة في نفس عملية الاختيار. يحتفظ بخامات GLTF وملفاته المضمنة. الملفات المستوردة تحفظ في مساحة التطبيق الخاصة لإعادة تحميلها بعد إعادة التشغيل.
- حركة اللاعب، جاذبية وقفز، تصادم AABB للأجسام المستوردة، ومنع اختراق الكاميرا للأجسام المسجلة.
- حفظ واستعادة إعدادات البيئة، موضع الشخصية، الوضعيات، المجسمات المستوردة وتحويلاتها محلياً.
- واجهة Android Native عبر React Native، واتجاه Landscape، وبناء APK من GitHub Actions.

## بناء APK من GitHub

1. أنشئ Repository جديداً.
2. ارفع **محتويات** هذا المجلد إلى جذر المستودع، بحيث يكون `package.json` في الجذر.
3. افتح تبويب Actions.
4. شغّل `Build AB Open World Native APK`.
5. بعد نجاح البناء افتح العملية ثم نزّل Artifact باسم `AB-OPEN-WORLD-NATIVE-APK`.

## استيراد المجسمات

من داخل اللعبة افتح Assets ثم Import model. اختر ملف GLB. لملف GLTF ذي الموارد الخارجية، حدد ملف `.gltf` وكل ملفات `.bin` والصور المرتبطة به في الاختيار المتعدد. المرآة تكتشف من اسم الـ Mesh نفسه، وليس اسم الملف.

## ملاحظات تقنية صريحة

- هذه إعادة بناء Native وليست ترجمة آلية لكل سطر من HTML. ملف HTML محفوظ كمرجع وظيفي، وقد أُعيد تنفيذ أنظمة الرسم والبيئة والشخصية والمرايا والعظام والأنيميشن والتصادمات في وحدات مستقلة.
- لم يتم حتى الآن إثبات نجاح بناء APK أو اختبار الأداء على جهاز فعلي من داخل بيئة إعداد الملفات هذه. نجاح GitHub Actions هو الاختبار التالي المطلوب.
- تصادم الأجسام المستوردة حالياً يعتمد حدود AABB، وليس Mesh collider دقيقاً لكل مثلث؛ وهو أخف على الأجهزة المحمولة، لكنه قد لا يطابق كل هندسة معقدة.
- نظام المرايا مقصود أن يعكس البيئة فقط ولا يعكس المجسمات، وفق المواصفات المتفق عليها.
- بعض وظائف HTML الثانوية/اللوحات الإضافية لم تُنقل كلها في هذه المرحلة؛ راجع MIGRATION_STATUS_AR.md.
